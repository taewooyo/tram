# 개발 흐름 공통 규칙 (flow-rules)

> 여러 스킬·서브에이전트가 **공유**하는 개발 규칙의 **단일 출처**다.
> 전에는 이 규칙들이 `OS.md`·여러 `SKILL.md`에 흩어져 중복됐다 → drift(옛 기준 잔존)의 원인.
> 이제 규칙 상세는 **여기 한 곳**에만 두고, `OS.md`는 이 카드를 가리키는 얇은 청사진으로 둔다.
> (배경·"왜"의 내러티브는 `OS.md`, "지금 지킬 것"은 이 카드.)

## 지킬 것

1. **검토 후 구현 (위험도 기준 게이트).** 새 기능·고위험·설계가 필요한 일은 PRD(①)·Plan(②)을 사람이 **확정·승인하기 전에는 구현을 시작하지 않는다.**
   작고 저위험한 변경만 `/quick`의 재활용 스캔·위험 감별 후 요구사항·PRD·Plan과 사전 게이트를 생략한다. `/coverage`는 테스트만 추가하는 커버리지 전용 예외로, 독립 리뷰·전체 테스트·목표 지표·라운드 안전판을 통과한 로컬 체크포인트 커밋만 허용한다.
   `/perf-loop`는 동작 보존 성능 개선의 독립 트랙으로, 재현 측정·정확성 게이트·성능 루브릭·되돌림/예산 기준을 먼저 확보한다. 새 동작·보안 보장·데이터 의미·설계를 바꿔야 하는 일은 이 예외에 포함하지 않으며 `/plan`으로 넘긴다. 자동 커밋·push는 하지 않는다.
   애매하거나 커지면 멈추고 `/plan`·`/start`로 승격한다. 풀 흐름의 게이트를 임의로 넘지 않는다 — 가장 중요한 안전장치.
2. **테스트는 구현의 일부.** 동작이 바뀌면 단위/통합 테스트를 **나란히** 추가·갱신한다. 테스트 없는 동작 변경은 미완료다.
   순수 문구·주석·포매팅처럼 동작이 안 바뀌면 테스트는 생략 가능하다. `/quick`도 `/verify` light 검증과 완료 보고는 생략하지 않는다.
3. **재활용 우선.** 새로 짜기 전에 **기존 코드·스킬·유틸을 먼저 조사**한다. 비슷한 게 있으면 재사용/확장한다.
4. **모든 산출물은 저장소 안에.** PRD·Plan·문서·스킬·훅·컨텍스트는 전부 이 저장소 안에 둔다.
5. **로컬은 가볍게, 외부는 무겁게.** 커밋은 진행하되 **푸시·머지처럼 되돌리기 어려운 일은 사람 확인 후.**
6. **실행 주체는 위험과 비용에 맞춘다.** 작은 순차 저위험 조사·수정·light 테스트는 메인이 직접 수행할 수 있다. full의 fresh reviewer와 실제 검증, coverage/perf의 독립 검토·측정·되돌림·예산은 유지한다. 배정과 자원 독립성은 [단일 오케스트레이션 계약](./start-experience.md)을 따른다.

> 코드·테스트 고유 컨벤션은 대상 프로젝트의 `AGENTS.md`와 프로젝트 컨벤션 카드를 따른다.
