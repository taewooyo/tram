# 코드 리뷰 루브릭 (review-rubric)

> `/verify` full이 독립 reviewer에게 전달하는 코드 리뷰 채점 틀의 단일 출처다.
> `/verify`가 이 카드를 읽어 프롬프트에 본문을 포함한다. 격리된 reviewer에게 자동 주입될 것으로 가정하지 않는다.
> 같은 축을 구체 근거로 평가해 `/impl`이 부족한 축의 결함을 수정하는 수렴 루프를 지원한다.

## 핵심 원칙

- **근거에 묶인 점수.** 모든 축의 0·1·2 레벨에 코드 `파일:줄`, 수용 기준, 테스트 이름·실행 출력 등 구체 근거를 붙인다. 2점도 “없음”만 적지 않고 검토한 경로와 동작을 적는다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
- **min-gate.** 레벨 0인 축은 블로킹이다. 합계 점수로 덮지 않는다.
- **열린 적대적 탐색.** 5축 밖의 결함도 계속 찾고 지적한다. 실제 블로킹 결함 또는 수용 기준 미충족은 점수와 별개로 통과를 막는다.
- **검토 한계 공개.** 필요한 파일·기준·실행 신호를 확보하지 못하면 검증 불가 이유를 보고한다. 근거 부족을 임의의 점수나 통과로 바꾸지 않는다.

## 5축 · 앵커 (각 0·1·2)

| 축 | 2 (통과) | 1 (경미) | 0 (결함·블로킹) |
|----|----------|----------|------------------|
| 정확성/버그 | 검토한 로직·엣지·경계·동시성에서 결함 없음 | 근거 있는 미검증 의심 경로 있음 | 실제 버그·경계 오류 |
| 테스트 품질 | 추가/변경 동작을 유효한 어서션으로 검증하고 관련 엣지를 덮음 | 경미한 엣지 1~2 누락 | 무어서션·항상 참·핵심 경로 미검증 |
| 재활용성 | 관련 기존 코드/유틸/스킬을 재사용하며 불필요 중복 없음 | 사소한 중복 | 기존 구현을 불필요하게 재구현/중복 |
| 단순성/과설계 | 요청 범위에 필요한 만큼만 구현, 변경으로 생긴 죽은 코드 없음 | 약간 장황 | 명백한 과설계·불필요 복잡성·변경으로 생긴 데드코드 |
| 컨벤션/규격 | 대상 프로젝트 카드·규격 준수 | 경미한 일탈 | 에러 형식·레이어 경계 등 규격 위반 |

대상 프로젝트의 실제 컨벤션 카드를 사용한다. 관련 없는 프로젝트 규칙을 강요하거나 점수를 위해 요청 밖 기능·추상화·테스트를 추가하도록 요구하지 않는다. 순수 문서 변경의 실행 테스트처럼 해당하지 않는 항목은 이유와 적용 가능한 검사 근거를 적어 평가한다.

## 점수 · 판정

- **점수 = (5축 레벨 합 / 10) × 100**, 가능한 값은 0~100의 10점 단위다.
- 예: 정확성2·테스트0·재활용1·단순2·컨벤션2 → 70점, 테스트 품질 0은 블로킹.
- **통과:** 적용 가능한 테스트/검사 통과 + Plan·PRD 또는 사용자 수용 기준 충족 + 점수 ≥ 90 + 0축 없음 + 축 밖 블로킹 결함 없음. 남은 1점 축은 개선 제안으로 보고한다.
- **구현결함:** 점수 < 90 또는 0축·테스트 실패·미충족·축 밖 블로킹이 있고, 구현/테스트 보완으로 해결 가능. 부족한 축의 인용 결함을 고치도록 제안한다.
- **설계문제:** 충족하려면 승인된 Plan 또는 PRD를 바꿔야 함. 재활용성/접근의 결함으로 설계를 바꿔야 하는 경우도 포함한다. 점수와 무관하게 이 판정을 우선한다.
- 검증 불가·형식 누락·도구 오류는 위 판정을 지어내지 말고 오류로 반환한다.

## 출력 형식

```text
## 리뷰 점수: NN/100 · 판정: 통과 | 구현결함 | 설계문제
## 축별 (레벨 · 근거 필수)
- 정확성/버그   [0|1|2] <파일:줄/수용 기준> 검토 동작 또는 결함 — 왜 / 수정 제안
- 테스트 품질   [0|1|2] <테스트 이름:줄/실행 출력> 검증 범위 또는 결함
- 재활용성      [0|1|2] <기존 구현과 변경 파일:줄> 재사용 조사 결과
- 단순성/과설계 [0|1|2] <변경 파일:줄> 요청 범위와 복잡성 근거
- 컨벤션/규격   [0|1|2] <적용 카드·변경 파일:줄> 준수 또는 위반 근거
## 블로킹
- 0축: 없음 | <축 이름 목록>
- 축 밖: 없음 | <블로킹 여부·파일:줄·무엇이 / 왜 / 어떻게>
- 수용 기준 미충족: 없음 | <항목과 근거>
## 근거 / 신호
- 테스트/검사 명령 · 종료 코드 · 통과 N/M · 검토 한계
```

이 루브릭과 `/coverage` 건강도는 0·1·2 앵커와 감사 근거 기록 방식을 공유한다. 축·계산식·종료 기준은 별개이며, min-gate는 코드 리뷰 통과 조건에 적용한다.
