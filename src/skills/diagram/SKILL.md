실행 주체는 [단일 오케스트레이션 계약](../../context/start-experience.md)의 직접 수행·위임 기준을 따른다. 아래 작업자 절차는 위임 시 적용하며 각 경로의 독립 검토·안전판은 유지한다.

## 실행 경계

현재 스킬 파일의 `../..`를 plugin root로 해석하고 `<plugin-root>/adapter.md`와 [공통 실행 계약](../../context/runtime-contract.md)을 먼저 읽는다. 대상 프로젝트는 사용자 지정 경로로 명시하며 plugin root와 혼동하지 않는다. 문서·명령의 상대 경로와 셸 cwd는 대상 프로젝트 기준이다. `<plugin-root>` 표기는 해석한 실제 경로로 치환하고 셸 경로는 인용한다. Native 도구·독립 검토 호출은 adapter를 따른다.


## 실행 역할

[단일 오케스트레이션 계약](../../context/start-experience.md)을 따른다. 메인은 이 스킬 전체 흐름을 읽고 직접 수행 또는 단계 배정을 선택하며 작업자는 사용자 질문·승인/전이·Task 갱신·재위임을 하지 않는다. 메인이 그릴 의미·범위·소유 HTML/PNG를 확정하고 단계별 역할을 배정한다. 작업자가 HTML 작성→실제 렌더→PNG 직접 확인→최대 4회 수정의 연속 작업을 수행하고 근거·횟수·남은 문제를 반환한다. 메인이 결과를 통합하고 요청 시 이미지를 검토한다.

# /diagram — 검증된 다이어그램 (HTML → 이미지)

도식을 디자인된 HTML/CSS로 만들고, 헤드리스 Chrome으로 PNG 스크린샷을 떠 **직접 눈으로 본다**. 의도와 다르면 고쳐 다시 찍는다. 최종 산출물은 검증된 PNG 이미지다.

HTML/CSS는 Mermaid 자동 레이아웃보다 색·카드·범례·배치를 자유롭게 디자인할 수 있다. 스타일은 `docs/diagrams/os-flow.html`과 `docs/diagrams/feature-flow.html`을 참고하거나 재사용한다. `/impl ↔ /verify`의 구현·검증 루프를 시각물에도 적용해 “안 보고 넘기기”를 막는다.

전달된 인자는 그릴 내용과 선택적 출력 경로다. 경로가 없으면 `docs/diagrams/<slug>.html`과 `.png`를 제안한다.

## 작업 루프

### 1. HTML 작성

배정된 작업자가 HTML/CSS로 `<이름>.html`을 디자인한다.

- 노드는 둥근 카드로, 사람·서브에이전트·훅·게이트 등 종류별 색을 구분한다.
- 화살표와 라벨, 하단 범례를 포함한다.
- 스크린샷 크기를 예측할 수 있도록 body에 고정 너비(예: `width:1000px`)를 둔다.

#### 설계 원칙 — “흐름은 흐름답게”

결정·분기·루프를 칩 한 줄로 나열해 표처럼 납작하게 만들지 않는다. 도식의 가치는 무엇이 갈라지고 되돌아오는지를 화살표로 한눈에 보여 주는 데 있다.

- **분기:** 결정 노드에서 결과별로 여러 갈래를 fan-out하고, 각 화살표에 결과 라벨을 붙인다.
- **루프:** 재시도·수정·재구현은 본류와 구분되는 점선·색의 되돌아오는 화살표로 그린다. “반복”이라는 글자만 쓰지 않는다.
- **탈출:** 통과·종료·에스컬레이션은 본류에서 벗어나는 화살표로 방향을 드러낸다.
- **의미:** 종류는 색으로, 의미는 라벨로 나타내며 범례에 색의 뜻을 명시한다.
- **도구 선택:** 단순 선형 흐름은 CSS 카드만으로 충분하다. 분기·루프백·합류가 있으면 인라인 SVG의 `<marker>`와 `<path>`로 화살표 방향·곡선·되돌아옴을 통제한다. `docs/diagrams/os-flow.html`의 구현 블록이 이 예다.
- **한눈 우선:** 한 화면에서 시작부터 끝까지 시선이 자연스럽게 흐르고, 곁가지와 루프가 본류와 즉시 구분돼야 한다.

### 2. 스크린샷

같은 작업자가 다음 헬퍼로 실제 PNG를 만든다.

   ```bash
   bash "<plugin-root>/scripts/screenshot-html.sh" "<이름>.html" "<이름>.png" [width] [height]
   ```

스크린샷은 `width × height` viewport만 캡처한다. 확인 단계에서 아래가 잘렸으면 height를 키워 다시 찍는다.

### 3. 확인 — 처음 보는 사람 기준

같은 작업자가 host adapter의 이미지 보기 도구로 방금 만든 PNG를 반드시 직접 본다. 만든 사람의 의도가 아니라 **처음 보는 사람의 눈**으로, 설명 없이 한눈에 이해되는지를 먼저 판정한다.

**A. 한눈 판단 (우선)**

- 5초 안에 전체 흐름(시작 → 끝)이 읽히고 시선이 자연스럽게 흐르는가?
- 결정·분기가 갈라지는 그림으로 보이는가, 아니면 칩을 나열한 표처럼 납작한가?
- 루프·되돌아감·에스컬레이션이 화살표로 드러나는가?
- 색과 범례만으로 종류를 즉시 구분할 수 있는가?
- 곁가지와 루프가 본류와 한눈에 구분되는가?

하나라도 아니오라면 잘림이 없어도 실패다. 설계 원칙으로 돌아가 다시 그린다. 납작한 경우에는 SVG fan-out·루프백 흐름도로 다시 작성한다.

**B. 기술 점검 (그 다음)**

- 범례를 포함해 아래가 잘리지 않고, 겹침·삐져나옴·글자 깨짐이 없는가?
- 노드·라벨·색, 화살표의 방향·연결이 의도와 일치하는가?

### 4. 재시도와 종료

작업자가 A와 B를 모두 통과하면 근거와 산출물을 메인에 반환한다. 하나라도 실패하면 HTML/CSS를 고쳐 2부터 반복한다. 최대 4회까지만 시도하고, 남은 문제가 있으면 현재 결과와 함께 보고하고 멈춘다.

## 완료 보고

메인이 작업자의 실제 실행 참조·PNG 확인 근거를 대조해 최종 PNG와 HTML 소스 경로, 렌더·확인 횟수, 남은 문제(있다면)를 보고한다. 이 스킬은 생성과 검증까지만 하며 커밋이나 PR 생성은 하지 않는다. Mermaid 빠른 초안이 필요한 경우 `<plugin-root>/scripts/render-mermaid.sh`를 쓸 수 있지만, 기본 경로는 이 HTML 스크린샷 방식이다.

## 수용 기준

- [ ] HTML/CSS로 디자인하고 PNG 스크린샷을 만든다.
- [ ] 분기·루프는 칩 나열이 아니라 fan-out·루프백 화살표로 나타내며, 필요하면 SVG를 쓴다.
- [ ] 작업자가 host adapter의 이미지 보기 도구로 PNG를 직접 보고 “처음 보는 사람” 기준의 한눈 판단을 먼저 한다.
- [ ] 납작하거나 읽히지 않으면 잘림이 없어도 실패로 보고 다시 만든다.
- [ ] 잘림·오류·의도 불일치가 있으면 스크린샷·확인 루프를 반복한다.
- [ ] 최대 4회로 무한 루프를 막는다.
- [ ] 최종 이미지와 HTML 소스 경로를 보고한다.

## 안전 규칙

- PNG를 보지 않고 통과시키지 않는다.
- 스크린샷 오류는 원문 그대로 보고하며 성공으로 추측하지 않는다.
- 저장 위치와 커밋 여부는 사용자의 요청 범위를 따른다.
