# 진행 상태 조회

[작업별 검증과 정책 관찰](../../context/start-experience.md#작업별-검증과-정책-관찰)의 status 경계를 따른다. 명시한 작업의 저장 관찰은 show로만 읽을 수 있으며 현재 요청을 모르면 해당 추천 유효성은 미확인이다. 이 조회에서 search·recommend·record·configure나 새 지식 조사를 시작하지 않는다. runtime 상태와 관찰 참고 정보를 구분한다.

현재 스킬 파일의 `../..`를 plugin root로 해석하고 `<plugin-root>/adapter.md`와 [공통 실행 계약](../../context/runtime-contract.md)과 [작업 시작·재개의 사용자 경험](../../context/start-experience.md)을 읽는다. 대상 프로젝트를 명시한다.

메인이 직접 `python3 "<plugin-root>/runtime/tram.py" status --project "<target>"`를 실행한다. 특정 작업은 `--slug "<slug>"`를 붙인다. 여러 작업이 있으면 식별 가능한 목록을 보여주고 재개 대상을 임의로 정하지 않는다.

[공통 표시 정책](../../context/start-experience.md#요약문서-안내)에 따라 작업 의미·유효성·차단 이유·다음 행동과 실제 존재하는 문서를 안내한다.

## 표 형태의 기본 출력

여러 작업은 `작업 | 진행 상태 | 다음 행동` 표로 먼저 보여준다. 작업명만으로 구분되지 않으면 slug를 함께 표시하며, 상세 조회 대상을 임의로 선택하지 않는다.

특정 작업의 상세는 `항목 | 현재 상태` 표로 보여준다. 행은 작업, 진행 단계, 승인, 검증, 막힌 이유, 다음 행동, 관련 문서 순서로 구성한다. 승인은 PRD·Plan 각각의 현재 유효성을, 검증은 실제 실행 결과와 현재 유효성·미실행을 구분한다. quick처럼 승인이 필요 없는 경로는 `해당 없음`으로 표시하며 승인 누락으로 설명하지 않는다. 관련 문서는 실제 존재하는 문서만 링크하고 없으면 `없음`으로 표시한다.

표의 값은 조회 결과에 근거한다. 미확인 값은 `미확인`과 이유를 표시하고 정상·통과로 추정하지 않는다. 긴 차단 이유·지원 제한과 실행 명령·검증 참조 같은 상세 근거는 표 아래에 덧붙인다. 미연결·조회 실패로 표를 채울 수 없으면 원래 오류와 다음 행동을 먼저 설명한다. 표를 만들기 위해 기록이나 문서를 생성하지 않는다.

상태 조회 뒤 [준비 상태와 문제 해결 안내](../../context/start-experience.md#준비-상태와-문제-해결-안내)에 따라 doctor를 보조 조회하고 정상 범위 또는 막힌 이유·첫 행동을 설명한다. 상태 조회 실패 시에도 원래 오류를 보존한다. 작업별 승인·검증 판단은 status를 따른다.

`effective_phase`·`next_action`·`approvals_valid`·`blocked`·`completion_issues`를 함께 읽고 현재 단계·승인 누락/변경·검증의 유효성·지원 제한·다음 행동을 설명한다. 승인과 증거가 낡았으면 필요한 검토·재검증을 안내하며 이 조회에서 실행하지 않는다. 조회는 작업자 배정·새 Task·지식 조사·작업 실행·init·전이·승인 기록·로그·marker·잠금 쓰기를 하지 않는다. 미연결·손상·모호함도 읽은 결과로 보고한다. 재개 요청은 [start](../start/SKILL.md)가 맡는다.
