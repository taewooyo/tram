Tram — 스킬 카탈로그

공통 정본의 18개 기본·전문 스킬이 각각 뭘 하는지 한눈에. 위 = 기능 개발 흐름(순서대로 ①→④, 게이트는 사람 검토) · 아래 = 목적별 받침 스킬. 색 = 종류(범례).

기능 개발 흐름 · 흐름 스킬기능 하나가 요청 → 요구사항 → 설계 → 구현 → 마무리로 흐른다. 풀 흐름은 사람 검토 게이트 통과 후 다음으로.
tram:init프로젝트를 연결하고 스택·컨벤션·검증 명령 후보를 조사한다. 기본 연결은 프로젝트당 한 번.요청 예: “Tram의 init 스킬로 현재 프로젝트를 연결해줘.”
tram:start작업을 시작·재개하며 프로젝트 자료를 먼저 조사한다. 필요한 결정만 묻고 PRD 확정·Plan 승인 뒤 구현·검증을 이어간다.요청 예: “Tram의 start 스킬로 검색 기능을 추가해줘.”
tram:status단계·승인 유효성·검증·차단 이유·다음 행동을 조회한다. 상태·로그·잠금을 쓰지 않는다.요청 예: “Tram의 status 스킬로 현재 상태를 알려줘.”

init으로 연결 → start가 아래 흐름 실행 · status는 언제든 조회 · 전문 스킬도 “Tram의 [스킬] 스킬로 …”라고 요청

① 요구사항·PRD무엇을 만들지 확정
tram:interview질문으로 요구사항을 캐낸다(한 번에 하나씩·냉정하게 압박). 선택적 수집 도구로 docs/prd/ 씨앗을 채움.언제: "요구사항 캐줘"
tram:prd러프 설명·수집 씨앗 → PRD 작성 후 reviewer로 검토·수정 루프를 돌려 확정.언제: "PRD 만들자"
확정 게이트 · 사람 검토
→
② 설계어떻게 만들지 계획
tram:plan확정 PRD로 구현 Plan 설계. 재활용할 기존 코드부터 조사(조사 작업자 1차 스캔 → 메인 갭 분류 → 표적 조사) 후 손댈 파일·단계·테스트 전략을 짠다.언제: "설계하자" · "Plan 짜자"
승인 게이트 · 통과 전 구현 금지
→
③ 구현만들고 검증
tram:impl같은 메인이 승인 Plan의 배정·통합·Task·전이를 맡는다. 작은 순차 저위험 작업은 직접 수행하고 필요 시 배정하며 /verify 판정대로 분기한다. full은 ≥90·0축 없음까지 결함만 보완.언제: "구현해줘"
tram:verifylight는 메인·구현자가 직접 테스트할 수 있고, full은 메인이 직접 생성한 fresh reviewer가 검사·5축 판정을 수행한다. 검증 담당 재위임 금지. 결과 전이는 메인이 맡는다.언제: "검증해줘" · /impl이 매 라운드 실행
→
④ 마무리기록·공개 (사람이 확인)
tram:commit변경사항을 의미 있는 단위로 로컬 커밋.언제: "커밋해줘"
tram:push로컬 커밋을 원격(GitHub)에 푸시. /retro 호출 흔적 게이트 검사. 되돌리기 어려운 일이라 확인 후.언제: "푸시해줘"
tram:pr커밋들을 분석해 PR 제목·본문을 LLM이 종합 → 사람 확인 → 템플릿 틀 확인 → gh로 PR 오픈.언제: "PR 올려줘"
빠른 트랙
흐름(요구·PRD·Plan)을 건너뛰는 저위험 경로
tram:quick작고 저위험한 변경을 종류 안 가리고 가볍게 처리 — 버그·QA·작은 스펙 변경. "조사 → 메인 위험 감별 → 직접 또는 위임 변경·테스트 → /verify light". 커지면 /plan·/start로 승격.언제: "가볍게 고쳐줘" · "간단한 수정이야"
루프 트랙 · 자기수렴 grind
객관 지표로 반복 · 정체·상한·오류 시 종료
tram:coverage명시적 adapter·프로필 목표. testPaths 안에서 테스트를 보완하고 adapter 측정(Python 또는 Kover XML 집계)로 측정. 대상 테스트·상승·독립 리뷰를 통과한 라운드만 커밋. 최대8라운드·30분.언제: /coverage · /coverage 90
tram:perf-loop재현 벤치·목표·정확성 기준 확보 후 후보 하나씩 변경. 측정 개선·/verify와 출력 동일성·6차원 ≥90 모두 통과하면 채택, 아니면 되돌림. 런북·라운드 로그 분리.언제: "속도 개선" · "성능 최적화 루프"
지식 · 문서
흐름을 더 정확하게 만드는 컨텍스트·산출물
tram:domain서비스 도메인 하나를 분석해 "정체·경계·관계"만 담은 문서(docs/domain/)를 만든다. 문서끼리 [[링크]]로 도메인 지도를 쌓음.언제: "도메인 정리해줘"
tram:diagram디자인된 HTML로 도식을 만들고 헤드리스 Chrome으로 스크린샷 → 직접 보고 검증하는 루프로 PNG를 낸다. (이 카탈로그도 /diagram 산출물)언제: "도식 그려줘" · "다이어그램"
메타 · 관측 (자기개선)
OS 자신을 돌아보고 측정
tram:retro방금 세션을 두 렌즈로 회고 — (A) 스킬 프롬프트 개선점 (B) 손댄 도메인 문서 변경점 → 사용자에게 직접 보고(파일 안 만듦, 사람 검토 게이트).언제: "회고" · 세션 마칠 때
tram:skill-stat스킬 호출 기록(skill-usage.log)을 집계해 어떤 스킬을 많이 썼는지 통계로 보여준다.언제: "스킬 통계"
