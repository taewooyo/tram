# 문서 작성 규칙 (docs/)

> 이 파일은 `docs/` 아래 문서를 만지는 순간 **자동 주입**되는 규칙 카드다(경로 매칭 = 결정적 주입).
> 스킬을 안 돌리고 맨손으로 문서를 고칠 때도 이 규칙이 따라온다. 격리된 서브에이전트에는 관련 카드를 직접 전달하거나 읽도록 한다.
> 규칙은 여기 한 곳에만 둔다(단일 출처). 실제 예시는 `docs/`의 기존 문서가 원본.

## docs/ 지도 (어떤 문서가 어디에)

```
docs/prd/<slug>.md            ① "무엇" — /prd가 수집(러프 초안·/interview 씨앗)부터 정제·확정까지 책임 (문제·목표·시나리오·범위밖·제약)
docs/plan/<slug>.md           구현 Plan (재활용 지도 → 직접 구현 → 테스트 전략)
docs/domain/<slug>.md         서비스 도메인의 정체·경계·관계 (/domain 이 유지)
docs/knowledge/<slug>.md      기존 문서가 없을 때 승인 범위 안에서 확정한 비도메인 프로젝트 지식
docs/knowledge/README.md      지식 문서의 얇은 색인
docs/diagrams/<name>.{html,png}  도식 소스(HTML)와 검증된 산출물(PNG)
docs/setup.md                  개발 OS 설치·도구·테스트 환경 안내
docs/perf/<slug>-loop.md      성능 루프 런북 (측정·환경·목표·절차, 라운드 기록 제외)
docs/perf/<slug>-rounds.md    성능 루프 R0·라운드 로그 (누적 요약·총 경과·채택/폐기 기록)
```

- **파일명 = 기능 slug** (kebab-case, 한 기능은 단계별로 같은 slug). 예: `signup-login-api.md`.
- 한 기능은 흐름을 따라 `prd → plan` 두 폴더에 **같은 이름**으로 쌓인다. 별도 requirements 파일·게이트는 두지 않는다.

## 문서별 틀 (있는 걸 따르고, 새 틀을 만들지 않는다)

- **PRD**: `## 문제 / 목표 / 사용자 시나리오 / 범위 밖 / 제약·조건 / 열린 질문`. 실패는 **상태코드 + `errorCode`**까지 명시. `/interview` 씨앗은 같은 경로에서 `> 상태: 수집 씨앗`으로 표시하며, `/prd`가 정제본으로 바꾼다. 정제 후에는 `검토 대기` → 사람 확정 시 `확정` 상태를 기록한다.
- **Plan**: `## 재활용할 기존 코드` → `## 직접 구현이 필요한 부분` → 테스트 전략. **재활용 조사 결과를 먼저** 적는다(새로 짜기 전 기존부터).
- **domain**: 정체·경계·관계만. 소스 구조(=/init 몫)는 다루지 않는다.

## 최신화 정책 — PRD·Plan은 스냅샷

- **PRD·Plan은 그 시점의 결정·설계 기록(스냅샷)이다.** 코드가 바뀌었다고 본문을 현재 코드에 맞춰 최신화하지 않는다. 동작의 진실 출처를 둘로 만들지 않는다.
- 각 문서 첫머리에 상태와 절대 연월을 표시한다: `> 상태: 초안 | 확정 | 구현됨 | 폐기 · YYYY-MM (스냅샷 — 코드 변경에 맞춰 최신화 안 함)`. 연월은 상태를 확인·기록한 시점이며, 확인하지 않은 과거 결정 날짜를 추정하지 않는다.
- 수집 단계는 기존 스킬의 상태 표식 `수집 씨앗`·`검토 대기`를 유지할 수 있다. **샘플은 용도, 미구현은 진행 상태**이므로 `미구현(샘플)`처럼 구분해 적는다. 수집 씨앗은 아직 정제·확정되지 않은 원재료임을 함께 표시한다.
- **진행 중인 사이클에서는** 수집 씨앗 정제·열린 질문 답변·검토 수정·확정/승인 상태 갱신을 허용한다. 스냅샷 정책이 `/prd`·`/plan`의 사람 검토 루프를 막는 것은 아니다. 구현 후에는 본문을 동작 설명서처럼 갱신하지 않으며, 상태 변경은 근거를 확인해 기록한다.
- **재작업은 과거 본문을 덮어쓰지 않는다.** 새 slug의 PRD·Plan으로 새 사이클을 시작하거나, 짧은 변경 이력 델타를 별도로 남겨 이전 결정과 연결한다. 같은 새 사이클의 PRD·Plan은 같은 slug를 쓴다.
- **현재 동작의 진실은 코드+테스트**, 도메인의 정체·경계·관계 설명은 `docs/domain/`에서 유지한다. 도메인 문서도 코드와 대조할 참고 자료이며, 어긋나면 코드·테스트를 확인한 뒤 `/domain`으로 갱신한다. `/retro`는 변경점을 찾아 갱신을 제안한다.
- **가치 차등:** PRD의 문제·범위 밖·결정 이유는 과거의 “왜”를 이해할 때 참조 가치가 있다. Plan은 구현 당시의 비계이므로 구현 후 최신화하지 않는다. 보존 가치가 없으면 링크·참조 영향을 확인해 명시적인 정리 작업에서 삭제할 수 있다. 이 정책만으로 기존 문서를 자동 삭제하지 않는다.

## 관례 (반드시 지킬 것)

- **한국어 서술.** 제목·본문·표를 한국어로. 첫머리에 "무엇을/왜"를 한 줄로.
- **[[링크]]로 도메인 지도를 잇는다.** 관련 문서는 `[[slug]]`로 연결하고, 새 도메인 문서를 추가하면 `docs/domain/README.md` 색인에 **한 줄 요약 + 링크**만 더한다(본문은 각 문서가 단일 출처).
- **단일 출처.** 같은 규칙을 여러 문서에 복붙하지 않는다 — 한 곳에 두고 나머지는 가리킨다(drift 방지).
- **상대 날짜 금지.** "다음 주" 같은 표현 대신 절대 날짜(YYYY-MM-DD).
- **모든 산출물은 저장소 안에.** 문서를 `/tmp`나 저장소 밖에 두지 않는다.

> 흐름·게이트 등 개발 전반 규칙은 [flow-rules.md](./flow-rules.md), 코드 컨벤션은 대상 프로젝트의 `AGENTS.md`와 프로젝트 컨벤션 카드를 따른다.
