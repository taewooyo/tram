# 프로젝트 심화 도입

기존 프로젝트를 충분히 이해하고 사용자와 확인한 지식을 이후 작업에 연결한다. init의 빠른 연결과 심화 조사의 차이를 설명하고 기존 프로젝트에는 심화 조사를 권장한다. 선택을 강제하거나 이미 표현한 선택을 다시 묻지 않으며, 생략해도 다른 작업을 제한하지 않는다.

## 조사와 질문

기존 코드·테스트·설정·문서·AGENTS.md·CLAUDE.md, 모듈 경계, 데이터·권한·외부 연동을 프로젝트 규모와 위험에 맞게 살펴본다. Git 저장소에 접근할 수 있으면 관련 이력에서 구조 변화와 반복된 문제를 확인할 수 있다. 이력은 변경 사실의 근거이지 제품 의도·보안정책의 증거가 아니다. Git이나 이력이 없으면 그 제한을 기록하고 조사를 계속한다. workspace로 기존 변경과 staged 삭제를 확인하고 기존 knowledge 후보와 선택형 harness 검색을 재사용한다. 관찰된 동작, 기존 문서의 주장, 사용자 확정 결정, 추정·충돌을 구분한다. 코드에 구현됐다는 사실만으로 제품·보안 정책의 의도를 확정하지 않는다.

아키텍처, 업무규칙, 외부 계약, 기술 지식, 운영, 보안, 개발 기준, 제품 진행 상태, 결정, 미해결 영역과 중요한 모듈·외부 의존·보안 경계를 조사한다. 조사 범위의 중요한 항목마다 요약 근거와 상태를 기록한다: `자료에서 확인`, `사용자 확인`, `해당 없음 — 이유`, `미해결 — 다음 질문/행동`. 이것은 조사 누락을 찾는 작업 메모이며 모든 파일을 전수 조사하거나 새로운 승인·runtime 상태 체계를 만드는 요구가 아니다. 프로젝트 규모·위험과 자료 양에 비례해 범위를 조절하며 sparse code는 중요한 영역을 덜 묻는 근거가 아니다. 기존 출처·사용자 결정·미결정 또는 해당 없음의 이유를 구분하고, 없는 정책을 지어내지 않으며 중요한 미결정은 영향과 함께 남긴다. 사용자 결정이 필요한 항목은 [사용자 질문](./user-questions.md)에 따라 직접 질문한다. 추천을 요청받으면 근거·대안·장단점을 제시하고 동의 전에는 확정 정책으로 쓰지 않는다.

틀리면 위험한 업무규칙·보안정책은 코드에서 추론할 수 있어도 사용자의 의도를 확인한다. 반면 코드·설정으로 결정 가능한 기술 사실은 먼저 조사하고, 가벼운 기술 선택은 코드가 충분한 경우 간결히 제안한다. 질문은 조사한 구체 영역, 코드가 답하지 못하는 이유, 잘못 판단했을 때의 영향을 담는다. 중요한 미결정은 coverage 기록에서 조용히 빠지지 않게 둔다.

## 문서 제안과 검토

기존 목적별 문서를 우선한다. 필요한 문서가 없으면 `docs/architecture.md`, `docs/business-rules.md`, `docs/contracts.md`, `docs/engineering-notes.md`, `docs/operations.md`, `docs/security.md`, `docs/standards.md`, `docs/tracking/status.md`, `docs/tracking/decisions/`, `docs/tracking/findings.md`를 해당 역할의 후보로 제안한다. 이는 선택 가능한 분류 예시이며 고정 세트를 일괄 생성하거나 빈 문서를 채우지 않는다. module-local 지침은 모듈마다 별도의 규칙·검증·보안 경계가 반복해서 작업에 영향을 주는 경우에만 제안하고, 이미 있는 `AGENTS.md`·`CLAUDE.md`의 사용자 본문을 바꾸지 않는다. domain의 정체·경계·관계는 기존 domain 경계를 따르고 중복하지 않는다.

프로젝트 지식 문서는 다음 작업의 판단이나 검증을 실질적으로 바꿀 정보를 우선한다: 코드만 읽어서는 알 수 없는 프로젝트 고유 사실, 결정 이유·제약·함정, 실제로 지켜야 할 규칙과 예외다. 일반론·코드로 쉽게 도출되는 설명·작업에 영향을 주지 않는 문장은 줄인다. 규칙과 기술 사실은 확인 근거·작동 방식·반례/금지 경계·구체적인 예외를 적어 다음 에이전트가 적용 여부를 판단할 수 있게 한다. 근거 없는 빈 문서를 구조 채우기 용도로 만들지 않는다.

문서별 경로·변경 내용·이유·근거·미해결 및 삭제된 경로 재생성 영향을 보여주고 사용자가 승인한 범위만 작성한다. 조사 동의는 쓰기 승인이 아니다. 사용자가 의도한 삭제와 staged 변경을 복원하거나 취소하지 않는다. AGENTS.md·CLAUDE.md의 사용자 본문과 다른 관리 block을 보존하고 승인된 최소 안내만 추가한다. ignore·공유 정책을 바꾸지 않는다.

작성 뒤 fresh 독립 reviewer에게 근거·확정 결정·추천·미결정·승인 범위와 결과 문서를 전달해 코드와의 모순, 누락, 추정 정책과 보존 경계를 대조한다. 독립 검토가 불가능하거나 중요한 미결정이 남으면 이해·문서화 완료를 주장하지 않고 이유와 다음 행동을 알린다. tracking은 제품 설명이며 승인·검증 상태 정본은 기존 runtime이다.

재개를 위해 허용된 `.tram/local/context/`에 최소 근거·결정·미해결을 남길 수 있다. 원문 개인정보·비밀을 저장하지 않고 기록이 불가능하면 대화에 남긴다. 이후 start/prd는 확인한 결정을 재사용하고 변경되거나 충돌한 근거만 다시 확인한다. 코드가 없는 새 프로젝트는 억지 도입 대신 start로 연결한다.
