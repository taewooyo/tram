실행 주체는 [단일 오케스트레이션 계약](../../context/start-experience.md)의 직접 수행·위임 기준을 따른다. 아래 작업자 절차는 위임 시 적용하며 각 경로의 독립 검토·안전판은 유지한다.

## 실행 경계

현재 스킬 파일의 `../..`를 plugin root로 해석하고 `<plugin-root>/adapter.md`와 [공통 실행 계약](../../context/runtime-contract.md)을 먼저 읽는다. [프로젝트 경험 규칙](../../context/project-experience.md)도 읽는다. 허용된 테스트 경로와 기존 사용자 변경을 확인하고 coverage의 명시적 체크포인트 커밋 계약은 유지한다. 대상 프로젝트는 사용자 지정 경로로 명시하며 plugin root와 혼동하지 않는다. 문서·명령의 상대 경로와 셸 cwd는 대상 프로젝트 기준이다. `<plugin-root>` 표기는 해석한 실제 경로로 치환하고 셸 경로는 인용한다. Native 도구·독립 검토 호출은 adapter를 따른다.


## 실행 역할

[단일 오케스트레이션 계약](../../context/start-experience.md)을 따른다. 메인은 이 스킬 전체 흐름을 읽고 직접 수행 또는 단계 배정을 선택하며 작업자는 사용자 질문·승인/전이·Task 갱신·재위임을 하지 않는다. 메인이 후보·adapter·Git 조건·허용 테스트 경로·채택·예산·중단을 결정한다. 작은 테스트는 메인이 직접 변경할 수 있으며 전체 테스트·측정을 직렬 실행한다. 메인이 매 라운드 fresh reviewer를 직접 배정하고 통과 뒤 확정한 개별 테스트 파일과 메시지의 checkpoint Git 실행만 작업자에게 맡긴다.

# /coverage — 프로젝트별 커버리지 어댑터 디스패처

## 런타임 기록

메인이 상태 조회·route·검증 강도·라운드와 `transition`·승인/증거 등록을 제어한다. 작업자는 배정된 소유 파일의 변경·검사·측정과 실제 `verify-run`만 수행하고 결과·실행 참조를 메인에 반환한다.

어댑터·도구·목표·허용 경로·전체 테스트 명령과 독립 검토 실행을 확보한 뒤 `configure --project PATH --file JSON`으로 `coverage.configured`·`reviewer.configured`와 명령을 확정한다. 신규 프로필 미설정은 실행하지 않는다. 모든 task 명령에 `--project PATH --slug SLUG`를 붙인다. `start --route coverage`와 `transition --action implement`로 진입한다. 각 라운드는 `transition --action verify` 후 `verify-run --command ID`로 전체 테스트·측정 증거를 수집하고 독립 reviewer 결과를 공통 계약의 JSON으로 `review --file JSON`에 등록한다. 코드 5축 리뷰와 아래 coverage 건강도 5차원은 별개다. 실패 라운드는 `transition --action implementation-defect`로 돌아가며 승인된 라운드만 아래 체크포인트 계약을 따른다. 추가 라운드가 필요하면 동일 결함 재진입 행동으로 구현 단계에 돌아가되 원인과 coverage 진행 기록을 구분한다. 최종 목표·종료 조건과 필수 증거가 충족된 경우에만 `transition --action complete`를 실행한다. runtime이 깨끗한 트리·예산·증거 조건을 거부하면 중단하고 보고한다. 거부를 피하려고 제품 변경이나 전체 트리 정리를 하지 않는다.

환경 준비는 adapter와 선택한 coverage 어댑터의 환경 검사를 따른다. 커버리지 도구와 대상은 프로젝트 프로필의 `coverage` 설정에서 명시적으로 선택한다.

## 어댑터 선택

- `.tram/project.json`에 `coverage.adapter: "kotlin-kover"`가 있으면 먼저 [Android/KMP JVM 어댑터](./adapters/kotlin-kover.md)를 읽고 따른다. 이때 Kotlin 프로필 검증과 `coverage-kotlin` 환경 검사를 먼저 수행한다. Python 아래의 `app/`, `tests/`, pytest-cov 명령·경로 조작을 Kotlin에 적용하지 않는다.
- adapter가 `python-pytest-cov`이면 [Python 어댑터](./adapters/python.md)를 적용한다. 신규 `.tram/project.json`에서 coverage 미설정이면 준비 사항을 알리고 시작하지 않는다. `.tram/project.json`이 없는 legacy `.codex/project-profile.json` 호환 호출에서만 기존 미설정 Python 기본값을 보존한다.
- 알 수 없는 adapter나 잘못된 Kotlin 설정은 실패로 처리하고 멈춘다. 지원되는 다른 adapter로 자동 추측하지 않는다.

## 공통 실행 계약

선택한 어댑터만 읽어 아래 실행 정보를 확정한 뒤 공통 루프를 진행한다. 어댑터는 입력·환경·측정 방법을, 이 문서는 반복·판정·체크포인트·롤백·감사 기록을 책임진다.

| 실행 정보 | 용도 |
|---|---|
| 목표 및 측정 대상 | 목표 판정과 기준선·라운드 간 동일 범위 유지 |
| 테스트 수정 허용 경로 | 변경·스테이징·롤백 경계를 정하는 디렉터리 목록 |
| 환경 검사 및 실행 명령 | 선택한 어댑터의 도구로 테스트와 측정 실행 |
| 결과 해석 및 테스트 범위 | 비교할 지표와 실제 실행한 테스트 범위 보고 |

커버리지는 허용 경로에 테스트만 추가·갱신하는 **저위험 전용 구현 트랙**이다. 프로덕션 코드는 수정하지 않는다. 시작 전 깨끗한 비기본 브랜치에서만 실행하며, 각 라운드의 대상 전체 테스트·측정·독립 리뷰를 모두 통과한 경우에만 테스트 변경을 로컬 체크포인트 커밋으로 남긴다.

> 일반 개발의 사람 게이트를 대신하지 않는다. 테스트만 추가해 객관적 지표를 개선하는 이 작업에 한해 반복 판단을 자동화한다. push·PR·merge는 수행하지 않는다.

입력과 기본값은 선택한 어댑터에서 해석한다. 실행 정보는 기준선부터 종료까지 고정한다. 프로필·도구·대상을 바꿔야 하면 현재 실행을 종료하고 별도 설정 작업으로 다룬다.

## 진행

### 1. 시작 전 확인

1. 어댑터의 입력·환경 검사로 실행 정보를 확정한다. 잘못된 프로필, 없는 대상·허용 경로, 실행 불가능한 도구는 보고하고 멈춘다.
2. `git status --porcelain`이 비어 있는지와 현재 브랜치가 `main`/`master`가 아닌지 확인한다. 변경사항이 있거나 기본 브랜치면 루프를 시작하지 않고, 깨끗한 작업 브랜치를 준비하도록 안내한다.
3. 시작 HEAD를 기록하고 기존 테스트 규약을 확인한다. `<plugin-root>/context/flow-rules.md`와 대상 프로젝트 컨벤션 카드를 읽는다.
4. 어댑터·목표·측정 대상·허용 경로·명령·테스트 범위를 사용자에게 요약한다. 설정 밖의 테스트나 플랫폼까지 검증했다고 표현하지 않는다.

환경·테스트 기준선이 확보되지 않으면 루프를 시작하지 않는다. 기존 테스트 전체가 실패하거나 기준 커버리지를 측정할 수 없어도 멈추고 보고한다.

### 2. 기준선 측정 및 라운드 선택

메인이 확정한 어댑터 명령으로 작업자가 대상 전체 테스트와 커버리지 측정을 직렬 실행해 기준선과 미실행 파일·라인을 기록한다. 목표를 이미 만족하면 테스트 변경 없이 6·7의 보고와 누적 기록 후 종료한다.

메인이 가장 작은 미실행 동작과 허용 범위를 선택하고 작업자가 **어댑터가 정한 테스트 수정 허용 경로**에 테스트를 추가·갱신한다. 기존 테스트 스타일과 픽스처를 재사용하고, 테스트 목적은 특정 내부 구현이 아니라 관찰 가능한 동작에 둔다. 프로덕션 코드와 설정은 수정하지 않는다.

메인은 작고 명확한 테스트를 직접 수정하거나 작업자에게 배정하며 필요한 코드·테스트 컨벤션을 읽도록 전달한다. 테스트 변경→대상 전체 테스트→동일 조건 측정은 직렬로 수행하고 공유 테스트 파일·측정 입력에 동시 쓰기를 허용하지 않는다.

### 3. 라운드 판정

각 라운드의 테스트 변경을 인정하려면 아래 조건을 전부 만족해야 한다.

1. 기준선과 동일한 어댑터 명령으로 대상 전체 테스트가 통과한다.
2. 동일 대상·동일 명령으로 잰 커버리지가 직전 승인 라운드보다 오른다. 비교에는 표시용 정수 반올림값이 아니라 보고서의 실제 백분율 또는 covered/total line 수를 사용한다.
3. 메인이 매 라운드 fresh 독립 reviewer를 직접 생성하고 공유 검토자 역할([`reviewer`](../../agents/reviewer.md))에 독립 리뷰를 맡겨 `통과`를 받는다. 대상은 이번 라운드에서 추가·수정한 테스트다. 검토 기준은 요구 동작을 실제로 확인하는지, 유효한 실패 조건을 만들고 있는지, 무어서션·항상 참·중복·구현 세부 결합 테스트가 아닌지다. 테스트 명령 결과도 함께 전달한다.

실패한 조건은 통과로 간주하지 않는다. 검토자 또는 테스트 도구가 오류·빈 결과를 내면 그 라운드를 멈추고 보고한다.

### 4. 체크포인트와 라운드 되돌리기

판정 통과 후 작업자가 `git status`와 diff·HEAD·branch·staged 상태를 반환하고 메인이 범위를 확인한다. 제품 변경이 테스트 수정 허용 경로 안의 테스트 파일로만 한정되고 민감 파일이나 사전 스테이징이 없을 때만 **이번 라운드의 개별 테스트 파일**을 메인이 확정한 메시지와 함께 작업자에게 배정해 스테이징·로컬 커밋한다. 실행 직전 HEAD·branch·파일 범위가 달라지면 작업자는 중단해 반환한다. 이번 실행의 runtime이 쓴 `.tram/tasks/<slug>.json`은 제품 변경과 구분해 보존하며 자동 스테이징·롤백하지 않는다. 다른 `.tram` 파일 변경은 임의로 이 예외에 넣지 않는다. 저장소 커밋 규약과 실행 host의 서명을 따르고, 메시지에 라운드와 전후 커버리지를 적는다. 커밋마다 테스트·커버리지·검토 결과를 진행 로그에 남긴다.

체크포인트 커밋은 HEAD를 바꾸므로 커밋 전 검증 증거는 최종 완료용으로 재사용하지 않는다. 마지막 체크포인트 뒤 같은 검증 라운드에서 메인이 배정한 필수 `verify-run`과 새 독립 reviewer 실행으로 현재 HEAD의 증거를 저장한 후에만 메인이 `complete`한다. 이 재확인은 새로운 테스트 추가 시도로 세지 않으며 기존 시간·토큰 예산을 늘리지 않는다. 검증 입력을 바꾸는 문서·기록도 저장한 뒤 최종 증거를 수집한다.

테스트 실패, 커버리지 후퇴, 리뷰 지적이면 메인이 확인한 승인되지 않은 라운드만 작업자가 되돌린다. 시작 시 깨끗한 트리였다는 전제와 더불어, 현재 diff 및 미추적 파일이 이번 라운드가 수정한 허용 경로 안의 테스트 파일에만 있는지 확인한다. 이 조건이 명확할 때에만 해당 개별 파일을 `git restore`하고, 이번 라운드가 만든 미추적 테스트 파일만 개별 경로로 제거한다. 전체 트리 대상 `git checkout -- .`, `git clean` 또는 `git reset --hard`는 사용하지 않는다. 범위를 증명할 수 없거나 허용 경로 밖 변경이 보이면 롤백도 하지 말고 즉시 중단해 변경을 보존하고 보고한다.

### 5. 반복 안전판

각 라운드 시작·종료에 한 줄 진행 상황을 남기고, 아래 중 하나라도 먼저 발생하면 중단한다.

- 최대 8라운드, 30분, 모델 사용량 60,000 토큰 중 하나에 도달.
- 커버리지가 2라운드 연속 오르지 않음.
- diff에 테스트 수정 허용 경로 밖 파일이 나타남.
- 같은 커버리지 목표를 달성하려면 제품 코드·스키마·설정 변경이나 설계 판단이 필요함.
- 기준 테스트 실패, 도구·서브에이전트 오류, 체크포인트 커밋 실패.

토큰 사용량이 실행 도구에서 확인되지 않으면 추정치를 실제 사용량처럼 보고하지 않는다. 라운드 수와 벽시계 상한을 지키며, 토큰 상한을 확인할 수 없는 런타임에서는 실행 가능한 사용량 한도를 적용한다. 무인 루프의 중단 조건을 임의로 늘리거나 해제하지 않는다.

### 6. 최종 보고

목표 달성, 상한 도달, 진척 없음, 범위 위반 또는 에스컬레이션 중 어떤 이유로 끝났는지 보고하고 멈춘다.

```text
✅ 커버리지 목표 달성 — 라운드 R · 시작 X% → 최종 Y% (목표 T%)
또는 ⚠️ 중단 — 최종 Y% (목표 T%), 사유: ...
또는 ↩ 테스트만으로 진행 불가 — /plan·/impl 검토 권고 (사유: ...)

[요약] 어댑터·측정/테스트 범위 · 승인 라운드별 커버리지 추이 · 추가 테스트 파일 수 · 대상 전체 테스트 결과
[건강도] 진척 인정/시도 라운드 · 효율·진척성·안전·품질·수렴 점수
[감사 로그] 라운드별 변경 경로 · 전후 커버리지 · 전체 테스트 결과 · reviewer 최초/최종 판정 · 체크포인트/롤백 · 안전판 발동 · 종료 사유
```

자동 push·PR·merge는 하지 않는다. 제품 코드 변경이 필요하면 안전판을 우회하지 말고 사람에게 보고한 뒤 일반 `/plan`·`/impl` 흐름으로 넘긴다.

### 7. 루프 건강도와 실행 누적

커버리지 목표 달성과 별개로 루프의 효율·안전을 감사 로그에서 계산한다. 테스트 품질 판정은 독립 reviewer의 결과를 사용하며, 건강도 계산으로 대체하지 않는다.

```text
건강도 = 진척 인정 라운드 / 전체 시도 라운드 (0~1)
```

시도는 테스트 추가에 착수한 라운드다. 실패·롤백·중단 라운드도 분모에 포함한다. 진척 인정은 대상 전체 테스트 그린 + 커버리지 상승 + reviewer 통과 셋을 만족하고 체크포인트 커밋까지 성공한 라운드만 센다. reviewer 첫 통과율은 최초 판정이 통과인 라운드 / 전체 시도 라운드로 계산한다(미검토 라운드는 통과로 세지 않음).

각 차원은 다음 기준으로 0·1·2점 중 하나를 선택한다.

| 차원 | 2점 | 1점 | 0점 |
|------|-----|-----|-----|
| 효율 | 목표 달성, 시도 ≤ 라운드 예산의 절반(기본 4) | 목표 달성, 절반 초과·예산 이내 | 목표 미달 또는 예산 초과 |
| 진척성 | 건강도 ≥ 0.8 | 0 < 건강도 < 0.8 | 건강도 = 0 |
| 안전 | 롤백·서킷브레이커·에스컬레이션 0건 | 범위가 확인된 테스트 롤백만 발생 | 서킷브레이커 또는 에스컬레이션 발생 |
| 품질 | reviewer 첫 통과율 ≥ 0.8 | 0 < 첫 통과율 < 0.8 | 첫 통과율 = 0 |
| 수렴 | 막힘·예산 중단 없이 목표 달성 | 목표 미달이나 승인된 진척을 남기고 다른 사유로 중단 | 막힘·예산 중단 또는 진척 없이 목표 미달 |

0라운드로 이미 목표를 만족하면 건강도·진척성·품질은 `N/A`다. 효율·안전·수렴은 확보된 기준선과 종료 근거로 계산한다. preflight에서 시작하지 못했거나 과거 감사 로그가 부족하면 계산 불가능한 값은 `N/A`로 적고 이유를 남긴다. 모르는 값을 0점이나 통과로 추정하지 않는다.

종료 후 대상 프로젝트의 `docs/coverage-health.md`에 실행마다 요약 한 행을 append한다. 없으면 제목·설명·아래 표 헤더로 생성한다. 기존 실행을 덮어쓰지 않는다.

```text
| 날짜 | 대상 | 시작→최종% | 라운드 | 건강도 | 효율·진척·안전·품질·수렴 | 결과 | 메모 |
|------|------|-----------|--------|--------|--------------------------|------|------|
```

날짜는 실행일의 절대 날짜(YYYY-MM-DD), 대상 칸에는 목표도 적는다. 메모에는 진척 인정/시도 수와 reviewer 첫 통과 수를 적는다. 표 아래에는 실행 HEAD·라운드 예산·종료 사유 및 6의 라운드별 감사 로그를 실행별 소제목으로 append해 점수의 근거를 보존한다. 같은 실행의 재보고는 새 실행처럼 중복 append하지 않는다.

이 문서 쓰기는 루프 종료 후 기록에만 허용되는 테스트 수정 허용 경로의 예외다. 라운드 중에는 쓰지 않고, 테스트 체크포인트 커밋에도 넣지 않는다. 자동 커밋·push하지 않고 사용자의 마무리 커밋 대상으로 남긴다. 기록에 실패하면 실패 사실과 계산 결과를 보고한다.

## 수용 기준

- [ ] 선택한 어댑터에서 입력·환경·목표·대상·허용 경로·명령을 확정하고, 시작 조건을 통과하지 못하면 루프를 시작하지 않는다.
- [ ] 테스트만 추가하며, 매 라운드는 대상 전체 테스트 통과·커버리지 증가·독립 reviewer 통과가 모두 있어야 승인된다.
- [ ] 승인된 라운드만 테스트 파일 경로를 골라 로컬 체크포인트 커밋한다. 실패 라운드도 범위가 확인될 때만 테스트 파일만 되돌린다.
- [ ] 최대 8라운드·30분·토큰 한도·2회 연속 정체·허용 경로 밖 변경 서킷브레이커가 동작하고, 목표 달성 또는 중단 사유와 감사 로그를 보고한다.
- [ ] 자동 push·PR·merge와 제품 코드 수정은 하지 않는다.
- [ ] 종료 시 건강도·5차원 루브릭을 감사 로그로 계산하고, 실행 요약 한 행과 근거를 `docs/coverage-health.md`에 누적한다. 0라운드·기록 부족은 `N/A`로 구분한다.

## 안전 규칙

- 라운드 중 테스트 수정 허용 경로 밖 수정은 즉시 중단 신호다. 종료 후 `docs/coverage-health.md` 기록만 예외다. 프로덕션 로직을 고쳐 지표를 맞추지 않는다.
- 숫자만 올리는 테스트를 진척으로 인정하지 않는다. 대상 전체 테스트와 독립 리뷰를 모두 통과해야 한다.
- 자동 커밋은 명시적으로 승인된 테스트 전용 체크포인트에 한한다. push·PR·merge는 금지한다.
- 되돌리기는 이번 라운드 테스트 경로만 대상으로 한다. 사용자 변경 가능성이 조금이라도 있으면 자동 삭제하지 않고 멈춘다.
- 예산·안전판에 닿거나 결과가 불확실하면 루프를 멈춘다.
