실행 주체는 [단일 오케스트레이션 계약](../../context/start-experience.md)의 직접 수행·위임 기준을 따른다. 아래 작업자 절차는 위임 시 적용하며 각 경로의 독립 검토·안전판은 유지한다.

## 실행 경계

현재 스킬 파일의 `../..`를 plugin root로 해석하고 `<plugin-root>/adapter.md`와 [공통 실행 계약](../../context/runtime-contract.md)을 먼저 읽는다. [프로젝트 경험 규칙](../../context/project-experience.md)도 읽는다. 벤치마크·정확성 경로와 기존 사용자 변경을 확인한다. 대상 프로젝트는 사용자 지정 경로로 명시하며 plugin root와 혼동하지 않는다. 문서·명령의 상대 경로와 셸 cwd는 대상 프로젝트 기준이다. `<plugin-root>` 표기는 해석한 실제 경로로 치환하고 셸 경로는 인용한다. Native 도구·독립 검토 호출은 adapter를 따른다.


## 실행 역할

[단일 오케스트레이션 계약](../../context/start-experience.md)을 따른다. 메인은 이 스킬 전체 흐름을 읽고 직접 수행 또는 단계 배정을 선택하며 작업자는 사용자 질문·승인/전이·Task 갱신·재위임을 하지 않는다. 작업자가 후보 자료·프로파일을 분석하고 메인이 후보 하나를 선택한다. 작업자의 변경·측정·정확성 검사, 메인의 fresh reviewer 배정과 6축 채택/폐기 판단, 작업자의 확인된 후보 파일/헝크 되돌림을 직렬로 연결한다. 측정 입력과 변경 파일에 동시 쓰기를 허용하지 않는다.

# /perf-loop — 게이트 달린 성능 개선 랄프 루프

## 런타임 기록

메인이 상태 조회·route·검증 강도·라운드와 `transition`·승인/증거 등록을 제어한다. 작업자는 배정된 소유 파일의 변경·검사·측정과 실제 `verify-run`만 수행하고 결과·실행 참조를 메인에 반환한다.

정확성 게이트의 선택 강도를 runtime에도 전달한다. 기본 `--strength full`; 착수 시 저위험·동작 보존 테스트 근거를 기록한 light만 `transition --action verify --strength light --reason TEXT`로 연다. light 라운드는 실제 `verify-run` 증거로 판정하며 코드 5축 리뷰 JSON을 만들지 않는다. full 라운드는 새 독립 reviewer를 요구하고 이후 light로 낮출 수 없다. 아래 성능 6차원·출력 동일성·측정·되돌림 조건은 둘 다 그대로 적용한다.

착수 게이트에서 벤치마크·정확성 명령을 확보하고 full이면 독립 검토 실행도 확보한 뒤 `configure --project PATH --file JSON`으로 `perf.configured`와 명령을 확정하고 full이면 `reviewer.configured`도 확정한다. `start --route perf`·`transition --action implement`로 시작한다. 모든 task 명령에 `--project PATH --slug SLUG`를 붙인다. 각 후보는 측정 후 verify 스킬로 선택 강도의 `transition --action verify --strength light|full`·`verify-run --command ID`로 증거를 저장하고 full일 때만 독립 `review --file JSON`을 등록한다. 기본 full의 5축 리뷰와 아래 성능 6차원은 별개다. 실패·폐기·다음 후보 진행은 `transition --action implementation-defect`로 구현 단계에 돌아가되 실제 사유·채택/폐기를 라운드 로그에 구분한다. 요구/설계 변경은 `requirements-problem`·`design-problem`으로 full 검토에 돌린다. 목표/종료 조건과 정확성·측정·필수 검토가 충족된 최종 상태에서만 `transition --action complete`를 실행한다. runtime의 라운드 상한·증거 거부를 우회하지 않으며 스킬 예산과 런타임 상한 중 먼저 닿는 조건에서 중단한다.

속도 개선을 반복하되 **측정되지 않은 승리**와 **조용한 동작 변경**을 막는다.
숫자가 없으면 채택하지 않고, 빨라도 결과가 달라지면 폐기한다.

입력: `<대상>` 및 벤치마크·입력·명시적 속도 목표.
대상이 없으면 무엇을 개선할지와 어떻게 측정할지 묻는다. 목표가 없으면 목표도 확인한다.
예: “정산 배치 CALC_METER, 대표 입력, 총 시간 ≤150초”.

이 트랙은 latency/throughput 개선만 다룬다. 메모리는 관측 가능한 부작용으로 점검할 수 있지만 별도의 최적화 목표로 확장하지 않는다. 정확성은 개선 대상이 아니라 반드시 보존할 조건이다. 기능 추가·근사 계산·캐시 일관성 변경 등 동작을 바꿔야 빨라지는 경우는 `/plan`으로 넘긴다.

## 독립 트랙과 실행 경계

동작 보존이 전제라 새 기능의 PRD→Plan→impl 흐름 대신 **측정 게이트 + 정확성 게이트**를 쓴다. 단, 보안 보장·데이터 의미·공개 규격·설계를 바꿔야 하는 후보는 이 예외에 포함되지 않는다.
공유 [flow-rules](../../context/flow-rules.md)와 대상 프로젝트 컨벤션을 읽는다. 운영 데이터·설정·인프라 변경이나 외부 부하 실행 권한을 성능 요청에서 임의로 확대하지 않는다.

## 0. 착수 게이트 — 재현·정확성·되돌림 확보

루프 전에 다음을 사용자 입력·기존 자료로 확정한다. 이미 아는 것은 다시 묻지 않는다.

1. **벤치마크:** 명령·대표 입력·데이터 규모를 확보한다. 없으면 먼저 최소 벤치마크/계측을 준비해 검증한 뒤 루프로 들어간다. 준비와 최적화를 같은 라운드에 섞지 않으며, 준비는 별도 커밋 후보로 표시한다(자동 커밋하지 않음).
2. **주지표·목표:** latency, 총 실행시간, throughput 중 하나와 단위·목표를 고정한다. 쿼리 수 등은 진단 신호로 기록하며 속도 실측을 대체하지 않는다.
3. **환경:** warm/cold·반복 순서·데이터·동시성·VPN/LAN·자원 조건을 고정한다. 데이터가 변하는 작업은 각 측정 전에 같은 입력 상태를 복구한다.
4. **정확성:** 기존 테스트와 before/after 산출물 동일성 기준을 정한다. 금액·정산은 값·키·시각까지 같아야 하며, 비결정적 필드는 사전에 합의한 정규화만 허용한다. 차이를 숨기려고 검증 기준을 바꾸지 않는다.
5. **작업 트리:** 시작 HEAD·전체 diff·미추적 파일을 확인한다. 사용자 미커밋 변경과 겹치는 대상은 분리한 작업 공간 또는 깨끗한 작업 트리를 확보하기 전에는 수정하지 않는다. 사전 변경·채택 변경·현재 라운드를 구분해 되돌릴 수 있어야 한다.
6. **상한:** 최대 100라운드와 정체 K=2를 유지한다. 사용자가 준 시간·토큰 상한은 더 이른 종료 조건이며 늘리거나 우회하지 않는다. 알려지지 않은 실제 토큰 사용량을 추정값으로 보고하지 않는다.

벤치마크·목표·동일성 검증·되돌림 중 하나라도 확보되지 않으면 최적화는 시작하지 않는다. 기준 테스트/검사가 실패해도 멈춰 보고한다.

## 1. 기준선과 문서 분리

같은 조건으로 **N≥3회**(기본 3, 필요시 늘림) 측정해 원시 값·중앙값·변동 폭을 남긴다.
측정 반복 수·노이즈 판정 방식을 변경 전에 고정한다. 기본 노이즈 폭은 각 묶음의 `max−min`이며, 전후 중앙값 차이가 두 묶음 중 큰 폭보다 커야 유의미한 개선으로 인정한다. 흔들림이 크면 더 측정하거나 환경을 안정화하고, 유리한 값만 고르지 않는다.

**최초 기준선 B는 고정**, 마지막 채택 상태 X는 다음 라운드 비교 기준이다. 원시 최초 기록을 덮어쓰지 않는다. 목표를 이미 만족하면 R0와 종료 보고만 남긴다.

문서는 프로젝트 안 `docs/perf/`에 두 개로 분리한다. 경로가 gitignore면 알리고 해결 전 자동 강제 추가하지 않는다.

- **`<slug>-loop.md` 런북:** 벤치마크·입력·주지표·목표·환경·정확성 기준·트리거·VPN 등 주의·루브릭·측정/되돌림 절차·정리 방법. 라운드 기록은 넣지 않는다.
- **`<slug>-rounds.md` 로그:** R0 기준선과 매 라운드의 변경·근거·원시 측정·판정. 상단 누적 요약과 루프 총 경과를 매번 갱신한다. 재개할 때 마지막 채택 상태와 환경이 일치하는지 확인하며, 다른 조건이면 별도 실행으로 기록한다.

```markdown
# perf-loop — <대상> · 라운드 로그
> 실행 방법: [런북](<slug>-loop.md). 이 문서는 라운드별 기록이다.
한 줄 요약(누적): 최초 baseline B → 현재 X (누적 개선 %) · 목표 T
루프 총 경과: 착수 YYYY-MM-DD HH:MM ~ 현재 · 누적 N분 · 완료 k (채택 a / 폐기 d)

## R0 · baseline · YYYY-MM-DD HH:MM
- 시간: 시작·종료 절대 시각 · 소요
- 측정: 명령·지표·단위 · 원시 값 [값들] · N회 중앙값·변동 폭 · 재현 환경
- 정확성: 기준 테스트 결과·출력 기준과 보관 위치
- 진단: 프로파일·핫패스 등 병목 근거
- 누적: 최초 B · 현재 B · 목표 T
```

## 매 라운드

### R-a. 후보와 기대 점수

작업자가 프로파일·핫패스·N+1·불필요 반복·배치화 등 근거에서 후보를 찾고 관련 기존 코드/유틸을 먼저 조사해 메인에 반환한다.
메인이 아래 6항목으로 후보들을 기대 채점해 기대이득/위험이 가장 좋은 **하나만** 고른다. 변경 전 수치는 가설로 표시하며 정확성·속도·규모를 검증했다고 쓰지 않는다.

후보가 ≥4개면 메인이 선택적으로 adapter의 독립 에이전트 실행으로 평가 작업자를 직접 배정해 독립 평가를 병렬화할 수 있다. 기준·루브릭·관련 컨벤션·프로파일을 직접 전달한다. 평가 에이전트는 수정·부하 측정을 하지 않는다. `Workflow`·`/loop` 같은 별도 도구가 설치되어 있을 것으로 가정하지 않는다.

### 6차원 루브릭 — 합계 100, ≥90 + 두 하드 게이트

| 항목 | 배점 | 채점 앵커 |
|------|-----:|-----------|
| ① 정확성 보존 | 30 | `/verify` 통과 AND 산출물 동일성 확인이면 30. 실패·미확인이면 0이고 채택 금지 |
| ② 속도 목표 | 30 | 목표 만족이면 30. 최초 B와 목표 T 사이의 실측 개선은 선형 부분점, 개선 없음/악화는 0 |
| ③ 측정 신뢰성 | 15 | 동일 조건 N≥3 전후 원시 값·중앙값·변동 폭과 노이즈 초과 개선을 확보하면 15. 숫자 없음·1회·노이즈 이내면 0이고 채택 금지 |
| ④ 반경/되돌림 | 10 | 좁고 격리되며 되돌림 확인이면 10, 여러 공유 경로를 건드리지만 격리 가능하면 5, 범위/되돌림 불명확하면 0 |
| ⑤ 스케일 지속성 | 10 | 대표 운영 규모와 더 큰 N에서 이득 근거 확보이면 10, 대표 규모만 확인하면 5, 장난감 입력/추측만이면 0 |
| ⑥ 유지비 | 5 | 복잡도 증가가 거의 없고 기존 패턴을 활용하면 5, 추가 관리 부담이 있으나 설명 가능하면 2.5, 불필요 복잡성·관리 부담이 크면 0 |

모든 항목에 파일:줄·측정치·프로파일·출력/검사 결과 근거를 붙인다. 근거 없는 가산점은 금지한다.
**latency:** 속도 점수는 `30 × clamp((B−Y)/(B−T), 0, 1)`이다(B>T).
**throughput:** `30 × clamp((Y−B)/(T−B), 0, 1)`이다(B<T).
Y는 후보 적용 후 중앙값. 누적 목표 점수에는 최초 B를 쓰고, 이번 개선 판단은 마지막 채택 X와 Y를 비교한다.
추가 항목/가중치가 필요하면 착수 전에 합계 100으로 합의하고 런북에 고정한다. 결과를 본 뒤 유리하도록 배점을 바꾸지 않는다.

### R-b. 변경 하나

메인이 선택한 후보의 소유 파일·헝크를 직접 구현하거나 작업자에게 배정한다. 작은 순차 저위험 후보는 메인이 직접 처리할 수 있다. 프로젝트 컨벤션과 테스트를 함께 적용한다. 현재 라운드의 전 상태·diff·생성 경로를 보관한다.
여러 후보를 한 라운드에 섞지 않는다. 큰 구조 변경·새 동작·인프라 변경이 필요하면 이 트랙에서 구현하지 않고 에스컬레이션한다.

### R-c. 재측정 — 측정 게이트

작업자가 기준선과 같은 조건으로 N회 재측정한다. 측정 중 입력·변경 파일에 다른 작업자의 쓰기를 허용하지 않는다. 마지막 채택 상태 X보다 유의미하게 개선했는지 위 노이즈 기준으로 판정한다. 효과 없음·악화·환경 변화·측정 실패는 통과가 아니다. 속도 점수가 누적으로 높아도 이번 라운드에 이득이 없으면 폐기한다.

### R-d. 정확성 게이트

메인이 [`/verify`](../verify/SKILL.md) 흐름을 읽고 검증 작업자를 직접 배정한다. full이면 매 라운드 fresh reviewer도 메인이 직접 생성한다. 기본 full이며, 금액·정산·보안·동시성은 반드시 full이다. light는 위험이 낮고 기존 테스트가 동작 보존을 충분히 덮는 경우에만 착수 때 근거를 남겨 선택한다.
full은 코드 리뷰 루브릭 ≥90·0축 없음 등 해당 스킬의 모든 통과 조건을 만족해야 한다. 성능 6차원 점수와 코드 리뷰 5축 점수는 별개이며 각각 기록한다.
`/verify` 통과와 사전 정의한 산출물 동일성을 **둘 다** 확보한다. 빨라졌더라도 하나가 실패하면 폐기한다. 검증 에이전트는 구현 에이전트와 분리한다.

### R-e. 실측 재채점과 채택/폐기

메인이 실제 측정·정확성·독립 검토 근거로 6축을 재채점하고 채택 또는 폐기를 결정한다. 작업자는 이 결정을 대신하지 않는다.

| 조건 | 결정 |
|------|------|
| 성능 총점 ≥90 AND 유의미한 실측 개선 AND 정확성 게이트 통과 | 채택: 다음 비교 기준 X를 Y로 갱신, 커밋 후보로 보존 |
| 총점 <90 또는 측정/정확성 게이트 실패·미확인 | 폐기: 이번 변경만 되돌림 |

메인이 폐기를 결정하면 작업자가 되돌린다. 되돌림은 라운드 전 상태를 기준으로 현재 후보의 파일/헝크와 이번에 만든 파일만 대상으로 한다. **시작 HEAD로 전체 reset하거나 전체 트리 restore/clean하지 않는다.** 이전에 채택한 미커밋 변경·사용자 변경·런북·로그를 보존한다. 소유 범위가 불명확하면 삭제하지 말고 중단·보고한다. 되돌린 후 diff와 관련 검사를 확인한다. 도구/하위 에이전트 오류는 가정으로 채점하지 않고 안전하게 되돌릴 수 있는 부분을 처리한 뒤 로그와 함께 중단한다.

**다음 라운드 전에 채택·폐기 모두 로그에 append**하고 상단 누적 요약·총 경과를 갱신한다. 기록 실패 시 다음 라운드를 진행하지 않는다.

```markdown
## R<n> · 채택|폐기 · YYYY-MM-DD HH:MM
- 시간: 시작 YYYY-MM-DD HH:MM · 종료 YYYY-MM-DD HH:MM · 소요 N분
- 후보: 무엇을 왜 변경했나 · 기대 점수와 가설 근거
- 변경: 파일·헝크·커밋 후보(실제 커밋이 있을 때만 해시)
- 측정: 명령·단위 · before X → after Y · 개선 %
  - 원시 값: before [값들] / after [값들] · N·중앙값·변동 폭·고정 환경
- 정확성: /verify 판정·강도·full 리뷰 점수/블로킹 · 출력 동일성 검증 방법·결과
- 루브릭: 정확성 _/30 · 속도 _/30 · 측정 _/15 · 반경 _/10 · 스케일 _/10 · 유지비 _/5 → 총점 _/100 · 항목별 근거
- 결정: 채택(다음 X 갱신) | 폐기(되돌림 범위·확인 결과·사유)
- 누적: 최초 B → 현재 X · 누적 개선 % · 목표 T
```

### R-f. 종료

- 목표 달성: **현재 채택 상태**가 목표를 만족하고 게이트가 통과함.
- 정체: 최근 K=2개 시도 라운드의 채택 이득 합이 기본 5% 미만이고 남은 후보 기대이득도 낮음. 폐기 라운드는 이득 0으로 센다. 임계치를 바꾸려면 착수 때 런북에 고정한다.
- 후보 고갈: 측정 가능하고 허용 범위에서 시도할 후보가 없음.
- 기본 최대 100라운드 도달, 또는 사용자 지정 시간/토큰 예산 도달. 실패·폐기도 라운드 수에 포함한다.
- 벤치마크 오염·검증 오류·되돌림/기록 실패·새 동작/설계 필요: 사유를 남기고 중단.

그 외에는 R-a로 돌아간다. 100번을 채우는 것이 목표는 아니다. 변경·측정·정확성 검증·기록은 직렬로 수행한다. 별도 반복 스케줄러를 사용하더라도 이 종료 조건을 초기화하거나 예산을 우회하지 않는다.

## 마침 — 보고하고 멈춤

```text
✅ perf-loop 종료 — R라운드 · 사유: 목표|정체|고갈|상한|예산|오류|에스컬레이션
[최초 기준선 → 최종 채택 상태] 지표·단위 B → X · 누적 개선 %
[채택] 라운드·변경·실측 이득·정확성 결과·성능 점수
[폐기] 라운드·원인·되돌림 확인
[남은 후보] 다음에 검토할 것과 이번 제외 이유
[문서] 런북·라운드 로그 · 총 경과
[코드 밖 개선] 인덱스·설정·인프라 등 별도 필요한 작업
```

자동 커밋·push·PR·merge하지 않는다. 계측 준비와 채택된 변경을 목적별 커밋으로 제안하며 메시지에는 before→after 수치를 남긴다. 설계/동작 변경이 필요하면 `/plan` 경로로 보고한다.

## 수용 기준

- [ ] 재현 벤치마크·주지표/목표·동일성 기준·되돌림 경계 없이 최적화를 시작하지 않는다.
- [ ] N≥3 원시 측정·중앙값·노이즈를 남기고 최초 B와 현재 채택 X를 구분한다.
- [ ] 6차원 루브릭으로 후보 하나만 고르고, 기대 점수와 실측 점수를 구분한다.
- [ ] 실측 개선·정확성 두 게이트 + 성능 총점 ≥90 모두 만족해야 채택한다.
- [ ] 폐기는 이번 라운드만 되돌리고 이전 채택·사용자 변경을 보존한다.
- [ ] 런북과 라운드 로그를 분리하고 R0 및 채택·폐기 모든 라운드를 기록한다.
- [ ] 목표·정체·고갈·최대 100라운드·예산·오류에서 종료하고 보고한다.
- [ ] 코드 밖 변경·새 동작은 별도 경로로 넘기며 자동 커밋·push하지 않는다.
