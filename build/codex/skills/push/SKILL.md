실행 주체는 [단일 오케스트레이션 계약](../../context/start-experience.md)의 직접 수행·위임 기준을 따른다. 아래 작업자 절차는 위임 시 적용하며 각 경로의 독립 검토·안전판은 유지한다.

## 실행 경계

현재 스킬 파일의 `../..`를 plugin root로 해석하고 `<plugin-root>/adapter.md`와 [공통 실행 계약](../../context/runtime-contract.md)을 먼저 읽는다. 대상 프로젝트는 사용자 지정 경로로 명시하며 plugin root와 혼동하지 않는다. 문서·명령의 상대 경로와 셸 cwd는 대상 프로젝트 기준이다. `<plugin-root>` 표기는 해석한 실제 경로로 치환하고 셸 경로는 인용한다. Native 도구·독립 검토 호출은 adapter를 따른다.


## 실행 역할

[단일 오케스트레이션 계약](../../context/start-experience.md)을 따른다. 메인은 이 스킬 전체 흐름을 읽고 직접 수행 또는 단계 배정을 선택하며 작업자는 사용자 질문·승인/전이·Task 갱신·재위임을 하지 않는다. 작업자가 repo·remote·HEAD·branch·올라갈 커밋을 준비하고 메인이 사용자 권한·대상·조건을 확인한다. 작업자는 확정된 정확한 push 인자만 실행하며 조건 변경 시 중단해 반환한다. 위임은 새 외부 권한을 주거나 샌드박스를 우회하지 않는다.

# /push — 로컬 커밋을 원격에 반영

이미 커밋된 로컬 변경을 **GitHub(원격)에 푸시**하는 스킬입니다.

> 역할 분리: `$commit`은 로컬 기록까지만, `$push`는 외부 공개를 담당한다. push는 남들이 보게 되고 되돌리기 어려운 작업이므로, **무엇을 올리는지 먼저 보여주고** 진행한다.

전달된 인자: `$push` 뒤의 사용자 메시지.

- 보통 비워서 호출한다 (현재 브랜치를 업스트림에 푸시).
- 특정 브랜치나 리모트를 지정할 때만 인자로 받는다.

## 진행 순서

### 1단계: 푸시 대상 파악

작업자가 다음 읽기 명령으로 무엇을 어디로 올리는지 확인하고 repo·remote·HEAD·branch·커밋 목록·확정 명령 후보를 메인에 반환한다. 독립 읽기는 실행 한도 내에서 병렬화할 수 있다.

```bash
git status -sb
git log @{u}..HEAD --oneline 2>/dev/null
git remote -v
```

- 올릴 커밋이 없으면 "원격에 이미 최신입니다"라고 알리고 종료한다.
- 업스트림이 없으면 새 브랜치로 간주하고 4단계를 따른다.
- 원격이 더 앞선 behind 상태면 3단계에서 안전하게 멈춘다.

### 2단계: 올라갈 내용 보고

메인이 이번에 푸시될 커밋 목록과 대상 브랜치를 사용자에게 한눈에 보여주고 권한·정확한 실행 인자를 확인한다. 이미 확보한 유효 권한을 반복 요청하지 않는다. 사용자가 처음부터 푸시를 명시했다면 바로 다음 단계로 진행할 수 있다. 단, 여러 커밋, `main`/`master`, 또는 민감해 보이는 내용이면 한 번 짚고 넘어간다.

### 3단계: 푸시

작업자가 실행 직전 준비한 HEAD·branch·remote·대상과 확정 인자를 대조하고 아래 명령을 수행한다. 조건이 달라지면 실행하지 않고 메인에 반환한다.

```bash
git push
```

- `rejected`(behind)면 원격에 새 커밋이 있다는 뜻이다. 작업자는 실패 원문을 메인에 반환하고 메인이 `git pull --rebase` 후 재시도할지 사용자에게 묻는다.
- 인증 오류 등 다른 실패도 메시지를 그대로 전달하고 멈춘다.
- 사용자가 명시적으로 요청하지 않는 한 `--force` 또는 `--force-with-lease`를 사용하지 않는다.

### 4단계: 업스트림이 없는 새 브랜치

`git push`가 업스트림 미설정으로 막히면 작업자는 메인에 반환한다. 메인이 현재 브랜치·origin·아래 확정 인자를 확인한 뒤 작업자가 origin에 연결해 푸시한다.

```bash
git push -u origin <현재-브랜치>
```

### 5단계: 결과 보고

작업자가 실제 실행 결과를 반환하고 메인이 푸시된 브랜치와 원격, 올라간 커밋 수와 해시를 보고한다. 원격이 GitHub면 PR 생성 여부를 선택적으로 묻는다.

## 안전 규칙

- push는 외부 공개다. 무엇이 올라가는지 먼저 보여준 뒤 진행한다.
- `rejected`가 떠도 임의로 force 하지 않는다.
- 비밀키, 토큰, `.env`가 포함된 커밋이 올라가려 하면 멈추고 알린다. 한 번 push되면 원격 히스토리에 남는다.
