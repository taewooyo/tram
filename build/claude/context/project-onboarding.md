# 프로젝트 심화 도입

기존 프로젝트를 충분히 이해하고 사용자와 확인한 지식을 이후 작업에 연결한다. init의 빠른 연결과 심화 조사의 차이를 설명하고 기존 프로젝트에는 심화 조사를 권장한다. 선택을 강제하거나 이미 표현한 선택을 다시 묻지 않으며, 생략해도 다른 작업을 제한하지 않는다.

## 조사와 질문

기존 코드·테스트·설정·문서·AGENTS.md·CLAUDE.md, 모듈 경계, 데이터·권한·외부 연동을 프로젝트 규모와 위험에 맞게 살펴본다. workspace로 기존 변경과 staged 삭제를 확인하고 기존 knowledge 후보와 선택형 harness 검색을 재사용한다. 관찰된 동작, 기존 문서의 주장, 사용자 확정 결정, 추정·충돌을 구분한다. 코드에 구현됐다는 사실만으로 제품·보안 정책의 의도를 확정하지 않는다.

아키텍처, 업무규칙, 외부 계약, 기술 지식, 운영, 보안, 개발 기준, 제품 진행 상태, 결정, 미해결의 각 영역을 살펴 기존 출처·확인 근거·사용자 결정·미결정 또는 해당 없음과 이유를 기록한다. 없는 정책을 지어내지 않고 중요한 미결정은 영향과 함께 남긴다. 사용자 결정이 필요한 항목은 [사용자 질문](./user-questions.md)에 따라 직접 질문한다. 추천을 요청받으면 근거·대안·장단점을 제시하고 동의 전에는 확정 정책으로 쓰지 않는다.

## 문서 제안과 검토

기존 목적별 문서를 우선한다. 필요한 문서가 없으면 `docs/architecture.md`, `docs/business-rules.md`, `docs/contracts.md`, `docs/engineering-notes.md`, `docs/operations.md`, `docs/security.md`, `docs/standards.md`, `docs/tracking/status.md`, `docs/tracking/decisions/`, `docs/tracking/findings.md`를 해당 역할의 후보로 제안한다. 고정 세트를 일괄 생성하거나 빈 문서를 채우지 않는다. domain의 정체·경계·관계는 기존 domain 경계를 따르고 중복하지 않는다.

문서별 경로·변경 내용·이유·근거·미해결 및 삭제된 경로 재생성 영향을 보여주고 사용자가 승인한 범위만 작성한다. 조사 동의는 쓰기 승인이 아니다. 사용자가 의도한 삭제와 staged 변경을 복원하거나 취소하지 않는다. AGENTS.md·CLAUDE.md의 사용자 본문과 다른 관리 block을 보존하고 승인된 최소 안내만 추가한다. ignore·공유 정책을 바꾸지 않는다.

작성 뒤 fresh 독립 reviewer에게 근거·확정 결정·추천·미결정·승인 범위와 결과 문서를 전달해 코드와의 모순, 누락, 추정 정책과 보존 경계를 대조한다. 독립 검토가 불가능하거나 중요한 미결정이 남으면 이해·문서화 완료를 주장하지 않고 이유와 다음 행동을 알린다. tracking은 제품 설명이며 승인·검증 상태 정본은 기존 runtime이다.

재개를 위해 허용된 `.tram/local/context/`에 최소 근거·결정·미해결을 남길 수 있다. 원문 개인정보·비밀을 저장하지 않고 기록이 불가능하면 대화에 남긴다. 이후 start/prd는 확인한 결정을 재사용하고 변경되거나 충돌한 근거만 다시 확인한다. 코드가 없는 새 프로젝트는 억지 도입 대신 start로 연결한다.
