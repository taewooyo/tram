# Codex 연결 규약

도구와 데이터의 루트를 구분한다. 이 파일의 부모가 설치된 Tram 루트다.
대상 프로젝트는 사용자 지정 경로 또는 cwd의 `.tram/project.json` 조상으로 찾는다.
설치 캐시의 절대 경로를 프로젝트 JSON에 저장하지 않는다.

- 스킬: 호스트가 제공한 스킬 목록에서 Tram 스킬을 선택하고 해당 SKILL.md를 읽어 실행한다. 별도 `Skill` 도구를 가정하지 않는다. 플러그인의 정확한 사용자 호출 표기는 실제 호스트에서 확인한다.
- 사용자 질문: [공통 질문 계약](context/user-questions.md)에 따라 현재 호스트에서 제공하는 `request_user_input` 또는 `request_user_input_async`의 실제 schema·모드·용도 제한을 확인하고 공통 계약에 따라 호출한다. 동기·비동기 도구의 반환 의미는 다르며 비동기 접수는 답변이 아니다. 필수 답변은 실제 응답까지 기다리고 독립 작업은 계속한다. 사용 불가·실패 시 같은 질문을 대화로 전달한다. 호출 접수만으로 UI 표시나 답변을 확인했다고 주장하지 않는다. 기능·모드 허용 여부는 호스트마다 다르므로 자동 전환하거나 전역 설정을 수정하지 않는다.
- 셸·편집: 제공된 `exec_command`·`apply_patch` 도구를 사용한다. 가용 도구 이름이 다르면 실제 목록에 맞춘다.
- 작업자 실행: 메인이 현재 host 도구 metadata에서 실제 생성·후속 배정·상태 조회·실행 참조 반환 기능을 확인해 사용한다. generic 작업자에게 공통 계약과 지정 단계·소유 파일·확정 명령·권한·반환 근거를 전달한다. 사용자 질문·승인/전이·Task 갱신·재위임을 금지하고, 종료·상태 확인 전 같은 파일에 중복 배정하지 않는다. 특정 도구명이나 지속 실행 기능이 항상 있다고 가정하지 않는다.
- 지원 제한: 필요한 생성·후속 배정·상태 확인 또는 실행 참조 기능이 없으면 지원 불가·부분 결과를 메인에 보고하고 해당 실행·완료를 보류한다. 작은 순차 저위험 작업·light 검증의 메인 직접 수행 및 full 독립 검증 경계는 설치 root의 `context/start-experience.md` 단일 오케스트레이션 계약을 따른다. 공통 스킬에는 host 도구명을 고정하지 않는다.
- 독립 검토: 메인이 매 라운드 fresh generic/reviewer 서브에이전트를 직접 생성해 `agents/reviewer.md` 본문·기준·대상·컨텍스트 카드를 전달한다. PRD·문서·자료 독립 검토는 지정 기준을 대조해 결과를 반환한다. runtime full 검증 라운드에서만 reviewer가 직접 `verify-run`·검사·판정을 수행하고 메인은 검산·등록한다. 플러그인 TOML 자동 역할 등록은 가정하지 않는다. 독립 실행이 없으면 full 검증 완료를 선언하지 않는다.
- 훅: `PLUGIN_ROOT`를 지원하는 호스트의 네이티브 등록을 사용한다. 프로젝트 `.codex/hooks.json`과 플러그인 등록을 동시에 활성화하지 않는다.
- Git·푸시·외부 계정 권한은 대상 프로젝트와 사용자의 명시적 권한을 따른다. Tram은 샌드박스를 우회하지 않는다.

실행 예: `python3 "<Tram 루트>/runtime/tram.py" status --project "<프로젝트>"`.
명령 실행이 아니라 Markdown 예시이므로 `<...>`는 실제 확인한 경로로 치환한다.

공식 근거: [플러그인 패키징](https://developers.openai.com/plugins/build/plugins), [훅](https://learn.chatgpt.com/docs/hooks).
